Сетевое программирование: UDP-чат, передача файла по UDP и TCP-чат.

## Требования

- Linux (например Ubuntu, Debian, Fedora, Mint).
- **.NET SDK 10** (не только Runtime). Установку см. в [официальной инструкции Microsoft](https://learn.microsoft.com/dotnet/core/install/linux).
- Терминал с поддержкой UTF-8.

Проверка установленной версии:

```bash
dotnet --version
```

## Сборка

Из папки с архивом:

```bash
cd Lab5
dotnet build Lab5.sln
cd ..
```

Выполнить конкретную программу можно так:

```bash
bash Run/ChatUdp.sh
```

Все пять скриптов находятся в папке `Run`. После распаковки можно также сделать `chmod +x Run/*.sh` и запускать `./Run/ChatUdp.sh`.

## Опыт 1. UDP-чат

Откройте **два терминала**.

Терминал 1: `bash Run/ChatUdp.sh`
- Локальный порт: `5001`
- Удалённый порт: `5002`
- IP: `127.0.0.1`

Терминал 2: `bash Run/ChatUdp.sh`
- Локальный порт: `5002`
- Удалённый порт: `5001`
- IP: `127.0.0.1`

Наберите текст и нажмите Enter; `/exit` завершает клиент.

## Опыт 2. Выбор и скачивание файла по UDP

На компьютере-сервере положите два файла `test.txt` и `temp.txt` в каталог
`SampleFile` и запустите:

```bash
bash Run/UdpFileServer.sh
```

Сервер слушает все IPv4-интерфейсы на UDP-порту `5003` и показывает список
доступных файлов. На компьютере-клиенте запустите:

```bash
bash Run/UdpFileClient.sh
```

Введите IPv4-адрес сервера, затем номер нужного файла. Клиент сохранит выбор
как `SampleFile/downloaded_test.txt` или `SampleFile/downloaded_temp.txt`.
Передача одного файла ограничена **8192 байтами** — это ограничение учебного
UDP-протокола из исходной работы.

## Опыт 2а. Обрыв передачи: TCP и UDP

Для сравнения поведения протоколов запустите на компьютере-сервере:

```bash
bash Run/FileTransferServer.sh
```

Сервер принимает TCP на порту `5004` и UDP на порту `5005`. На клиенте
запустите:

```bash
bash Run/FileTransferClient.sh
```

Введите IP сервера, протокол `1` (TCP) или `2` (UDP), путь к файлу. В поле
`Отправить байт перед обрывом` укажите `0` для полной передачи либо небольшое
число, например `10`, чтобы клиент специально закрыл передачу раньше конца.

На сервере результат будет показан так:

- TCP сразу видит закрытие потока и сообщает, сколько байт не хватило;
- UDP не имеет соединения и события закрытия, поэтому сервер не получает
  уведомление об обрыве: он обнаруживает проблему по тайм-ауту или по
  несовпадению размера/числа пакетов и показывает неполный `.part`-файл.

## Опыт 3. TCP-чат

Терминал 1: `bash Run/ChatTcpServer.sh` (сервер на порту 8888).

Терминалы 2 и 3: `bash Run/ChatTcpClient.sh`, укажите разные имена, IP `127.0.0.1`, порт `8888`. Напишите сообщения друг другу.

## Другой компьютер в локальной сети

Замените `127.0.0.1` на IPv4-адрес компьютера-сервера. Например, узнайте
IPv4 сервера через `hostname -I` или `ip -4 addr`. При необходимости
разрешите UDP `5003` (файловый сервер), UDP `5001/5002` (UDP-чат), UDP `5005`
и TCP `5004` (сравнение передачи), а также TCP `8888` в брандмауэре.
Сетевые адреса должны быть достижимы между компьютерами.

## Отличия от Windows-проекта

- Целевая платформа изменена с **.NET Framework 4.7.2** на кроссплатформенный **.NET 10**.
- Классические `.csproj` заменены SDK-проектами; логика пяти приложений сохранена.
- Файлы `.bat` заменены `.sh`, но запуск через `dotnet run` работает без них.
- Получатель файлов сохраняет полученный файл и **не открывает его автоматически**: это более предсказуемо на Linux и исключает запуск переданного по сети файла.
